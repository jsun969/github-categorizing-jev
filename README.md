# github-categorizing-jev

Organize GitHub starred repositories into user-defined Star Lists with **Jev**, TypeSafe's decision model.

The goal is to turn a large collection of uncategorized stars into useful lists without manually reviewing every repository. You define the categories; the application gathers repository information; Jev judges which lists each repository belongs to.

**Current status:** the application has a working web shell and health-check API, and the official TypeSafe SDK is installed. GitHub import, classification, and the preview interface are not implemented yet.

## Intended workflow

1. **Define your categories.** Specify Star List names and descriptions that explain what belongs in each list. Categories are user-defined, not generated by Jev.
2. **Load your stars.** Fetch your starred GitHub repositories and their existing list memberships.
3. **Gather context.** Fetch each repository's available README, description, and metadata, such as topics and primary language.
4. **Classify with Jev.** Evaluate the repository against your category definitions. Classification is **multi-label**: a repository can belong to more than one list, such as both `AI` and `Developer Tools`.
5. **Preview the results.** Show the proposed list memberships before making any changes on GitHub.

The current product scope is **preview only**. Category definitions and proposed assignments must not create or modify GitHub Star Lists during this phase.

## Why Jev

[Jev](https://docs.typesafe.ai/concepts/system-one) understands natural-language context and returns typed decisions and probabilities rather than generated text. That fits a workflow where the categories are known and the application needs structured classification results.

For multi-label classification, list membership can be evaluated independently rather than forcing every repository into a single competing category. Application code owns data fetching and the workflow; Jev supplies the semantic judgments.

The project uses the official [`@typesafe-ai/sdk`](https://docs.typesafe.ai/sdk/javascript), which includes TypeScript types. It is installed but not yet connected to the application.

## Scope and open decisions

- **Multi-label classification:** one repository may match several lists.
- **Preview first:** no automatic writes to GitHub Star Lists in the current scope.
- **SQLite persistence:** intended for local storage, but integration and the data model are deferred. What to retain and how to reuse it are still to be decided.
- **Existing memberships:** preservation and reclassification behavior remain to be decided before adding any write-back workflow. A preview does not change existing memberships.

## Local development

### Requirements

- Node.js **22.12.0 or newer**.
- pnpm **10.33.0**, as specified in `package.json`.

### Run the application

```sh
pnpm install --frozen-lockfile
pnpm dev
```

Open [http://localhost:3000](http://localhost:3000). The current home page provides a **Check API** button that calls `GET /api/health`. A successful response is:

```json
{ "status": "ok" }
```

No GitHub or TypeSafe credentials are required to run the current web application. It does not fetch stars or make Jev requests yet. When the SDK is integrated, its `TYPESAFE_API_KEY` must remain server-side.

### Commands

| Command | Purpose |
| --- | --- |
| `pnpm dev` | Run the Vite development server on port 3000. |
| `pnpm typecheck` | Check TypeScript without emitting files. |
| `pnpm build` | Build the application for the Node.js server runtime. |
| `pnpm start` | Run the built server from `.output/server/index.mjs`; run `pnpm build` first. |

### Earlier experiments

The `scripts/` directory contains standalone Star List experiments and [API notes](scripts/GITHUB_STAR_LIST_API.md). They are not part of the application's preview workflow.

Some experiments can create GitHub lists or replace a repository's list memberships. Review their behavior before running them; the application's preview-only scope does not make these scripts read-only.
